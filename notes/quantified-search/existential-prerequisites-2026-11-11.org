#+TITLE: Existential-action prerequisite tracing
#+DATE: 2026-11-11

* Scope
Generic prerequisite tracing for existential transition actions, with a regression
pair comparing explicit action annotations/native stores against existential
parameters/pointwise quantified updates. Benchmark only the German and Chandra
generated VMT inputs in quantified-transition-systems, using the preceding
scalar/guarded-frame implementation as the baseline.

* Change
Countermodel action-requirement extension now recognizes existential witness
instances in an encountered quantified-transition path, at an asserted source
frame. Theory-specific recognition checks that the formula is exactly the
binder's witness implication for the actual capture tuple. It rechecks the helper
and implication using non-completing model evaluation. False observations stop
expansion; unknown observations remain explicit frontiers. It then traces the
observed body through the existing action-requirement machinery, preserving
source conditions, witness applications, and capture frames. The observed body
is never asserted as a refinement lemma.

Full witness instances and source frames deduplicate body traversal within each
model. All lookups, model queries, and further tracing share the guidance work
budget. Named actions keep their existing path. ActionRequirement provenance
uses the existential binder helper name when no named action annotation exists.

The when-unproductive schedule now admits completed cycles as well as expanded
and value nodes. It still excludes violated instances, unknown/unsupported
frontiers, evaluation failures, and exhausted traces. This matters for German's
MemData/AuxData explanations, which previously prevented prerequisite extension
from running at all.

* Regression design
prerequisite_explicit_action.vmt and prerequisite_existential_action.vmt have the
same observable enabled/data state, initializer, and property. One exposes a free
per-step parameter, named write/idle choices, and store. The other uses an
existential parameter and a universally quantified pointwise update.

The driver regression checks five BMC queries for both encodings and requires a
selected initializer instance whose trace ancestry passes through the action
prerequisite. It also checks equal instantiation counts with profiling enabled
and disabled. A separate Z3 oracle compares the transition formulas for all four
Boolean selector cases and an arbitrary shared parameter, including array
extensionality; existentially projecting the auxiliary parameter yields the same
observable transition relation. Invalid selector combinations are excluded in
the explicit encoding. A focused regression checks inactive/unknown helpers,
false/unknown witness implications, rejection of non-witness formulas, preserved
capture frames, and work-budget exhaustion.
