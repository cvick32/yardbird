#+TITLE: Scalar predecessor tracing and guarded frame equations
#+DATE: 2026-11-11

* Scope and implementation
Only the generated VMT inputs german.ctc.cub.vmt (Cubicle) and
chandra_buggy.in.vmt (Lambda), from the original twenty-case
quantified-transition-system sample, are benchmarked here.

Start from the capture-preserving implementation plus existential-action tracing.
Scalar state leaves now use the same asserted-transition equation lookup as array
reads. Initial scalar equations can be recovered from quantified initializers.
Tracing recognizes registered state leaves and respects the existing current /
predecessor ordering and asserted-frame bounds; opaque witness arguments remain
untouched.

Trace-only equation compilation indexes scalar assignments and traverses guarded
implications. It records guards at their positions among enclosing binder
instances. Validation checks witness/helper instances and guards in source order.
A false guard disables that equation; an unknown guard yields an explicit
undetermined frontier without a candidate lemma. Missing instances remain full
helper-guarded binder instances. Observed equations and model equalities are not
asserted as theory lemmas.

Quantified variables absent from a scalar demand receive declared seed terms of
the matching sort. Actual helper captures and existential witness applications
remain literal. Ordinary equation search and partial requests retain their
existing compilation behavior. No new CLI switch or serialized trace variant.

* Validation
All 509 library tests pass, including two new regression tests. The focused test
checks scalar and array demands, guards before nested helpers, false and unknown
guards, missing witness instances, preserved witness applications, and exclusion
of unasserted outgoing transitions. The driver regression completes checks 0--4
with scalar assignments and guarded array frames and observes scalar transition
and initialization instances. Existing regressions continue to cover opaque
witness captures and existential witness frontiers.

Final test harness: release dependencies, with optimization and LTO disabled only
for the library test harness using the recorded rustc wrapper. Normal release
build settings are retained for benchmark executables. Formatting and whitespace
checks pass. Raw logs, scripts, input lists, hashes, and profiles are under
benchmark_results/scalar-guarded-frames/.

* Measurement protocol
Primary runs use depth 5 (checks 0--4), a ten-second cooperative timeout, and one
second of external grace. A completed check counts only if its completion time is
within the stated budget. Timing runs are sequential and unprofiled, without
concurrent compilation. Diagnostic profiles are separate.

* Results
24 runs total, restricted to these two inputs. The primary ten-second comparison
with the original guided4096 configuration (supplement scheduling) improves
Chandra from one completed check to two. German stays at one. Exact grounding
produces the same depth counts. Native Z3 completes all five checks in 0.265 s
(German) and 0.668 s (Chandra).

Changing only the guidance schedule to immediate recovers Chandra at depth five.
The initial run completes in 8.101 s. Three independent unprofiled repetitions
complete all five checks in 7.851, 7.852, and 7.905 s: median 7.852 s. Each installs
207 instances. The preserved old binary, with exactly the same immediate-guidance
configuration and ten-second limit, completes only check 0 in all three repeats.
Thus the gain needs both the tracing change and the immediate schedule; it is
not a five-check recovery under the original supplement configuration.

| Input | Old checks / 5, 10 s | New checks / 5, 10 s | Configuration / timing |
|---+---+---+---|
| Chandra | 1 | 5 | immediate guidance, 7.852 s median, 3/3 confirmations |
| German | 1 | 1 | supplement, immediate, larger trace budget, exact grounding, or proved-prefix reuse |

A 16,384-work immediate-guidance screen also completes Chandra in 7.754 s;
raising the trace budget is unnecessary because the 4,096-work configuration
confirms reliably. Proved-property reuse with supplement scheduling remains at
two checks. No claim of beating Z3: Chandra still takes roughly twelve times the
native Z3 wall time in this measurement.

German reaches three checks with a thirty-second immediate-guidance limit.
A 120-second comparison reaches four checks on both binaries; neither completes
check 4. The fourth check (depth 3) completes at 99.452 s after the change and
108.221 s before it. These single extended runs do not establish a repeatable
speedup. The new run is externally stopped at 121 s and its partial progress file
supplies the completed-depth evidence. The ten-second score remains one check.

* Trace evidence and remaining German gap
The new five-second German diagnostic contains 66 violated quantifier-instance
nodes, versus seven in the saved five-second diagnostic, and now follows the
MemData, AuxData, and Exgntd scalars. Trace counts are diagnostics, not timing or
completion scores. Scalar tracing is active but does not close the benchmark.

A full Chandra immediate-guidance profile completes all five checks and records
41 violated guarded-instance nodes and 53 successful frame-guard observations.
There are no evaluation-failed or inconsistent-step nodes. This confirms that
the new guarded-equation path is exercised on the actual benchmark, in addition
to the focused synthetic regressions.

German's saved stalled trace (model 46, depth 1) isolates a remaining semantic
search gap. The active store action (source lines 122--139) requires
CacheState(witness) = Exclusive, updates AuxData from Store_data, and preserves
MemData and Exgntd. The scalar value trace follows those equations but ends in
cycles through MemData/AuxData and Store_data/AuxData. It does not turn the
existential action's enabling cache read into an initializer demand. The source
initializer at line 490 makes every CacheState entry Invalid, so that demand
would expose the missing initializer instance at this action witness.

This VMT input defines actions as disjunctive existential bodies, without :action
metadata. The existing action-requirement extension therefore does not recover
this prerequisite from a named action entry. The next targeted capability is to
trace enabling conjuncts of the encountered existential action body, preserving
the same actual witness/capture tuple, and carry those reads into initializer /
predecessor matching. That is distinct from merely raising budgets or tuning
term costs. It is identified here but not implemented by this patch.
