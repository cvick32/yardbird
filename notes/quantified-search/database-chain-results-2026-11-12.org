* Implementation
- Preserve the existing exact helper captures and full-instance validation.
- Reserve half the remaining prerequisite-stage work for relational matching.
- Run matching again after prerequisite tracing exposes concrete witness facts.
- Feed known Boolean observations to the clause agenda; skip unknown values.
- Allow validated background-axiom instances to use those concrete observations
  as provenance, rather than requiring an opaque unsupported helper.
- Queue observed helper demands before general source helpers.

Policy arithmetic is in src/policy/effort.rs. Stage ordering is in
src/countermodel.rs; tuple matching and observation provenance remain in
src/theories/quantifiers/countermodel_relations.rs. Observations are candidate
hints only, never asserted facts. No benchmark-specific name checks were added.

Observation ingestion alone and demand-first ordering alone did not improve the
database screen. The post-prerequisite pass selected 14 relational instances;
accepting concrete observation roots raised that to 32 in the five-second profile.
The combined change is the version measured above.

* Validation
All 515 library tests pass. Regressions cover exact capture preservation, unknown
observation exclusion, bounded work, action-local relational guards, and the same
kind of guard supplied as a background axiom. The integration tests require a
selected relational instance with prerequisite provenance, not merely eventual
solver success.

The original twenty quantified-transition-system VMT cases were rerun sequentially
at depth5, ten seconds, immediate scheduling, and 4096 guidance work. All prior

prefix times were reproduced by the longer database run. No statistical timing
