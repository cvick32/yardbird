* Scope and measurement
Both array axioms and input quantifiers remain in Yardbird for every guided
configuration. Native Z3 is the comparison. No preprocessing change is proposed.
A completed check means the entire property at one bounded depth was UNSAT.
Depth 20 means completing checks 0 through 19; it is not an unbounded proof.
Timeouts retain only completed checks within the wall budget.

The archived-results.csv table includes per-case coverage; archived-depths.csv
contains completion times for each check. archived-evidence.jsonl contains the
run dates, source revisions, binary/input hashes, configurations, and compact
results. Dirty source revisions alone do not identify the experimental build:
use the binary hash and archived run directory together. Raw solver journals,
full source snapshots and binaries remain in local benchmark_results/. They are
not included in the PR. Early screening runs use different limits; consult each
run's metadata before comparing them with depth-20/500-second confirmations.

The historical user result at commit 1f5d246 (six full completions) has not been
reproduced here. Matching its flags on another commit does not reproduce it.
All timing claims below describe individual sequential runs, release builds with
--no-default-features, with profiles and journals disabled for confirmation.
Small timing differences are not established statistical improvements.

* Retained options
- Source captures: preserve an intact helper argument tuple through extraction.
  In the earlier Tomasulo run, time through check 2 fell from 35.85s to 20.41s.
  Literal request bindings remain literal and every candidate is revalidated.
- Read frontiers: the combined capture/frontier run reached check 2 in 16.62s
  versus guided 36.07s. Reserve bounded discovery work and prefer demanded read indices
  inside the existing guided schedule; retain ordinary fallback work.
- Read support: interleave relevant single-variable universal instances and
  complete read-over-write equations over frozen source indices. Preserve
  satisfied candidates across models and validate again before installation.
  The former read-binder and complete-read switches are folded into this option.
- Proved-property reuse and certified instances: retain the original proved
  frame. Substitute only recorded arbitrary property witnesses, with a shared
  per-depth budget and exclusions for auxiliary property restrictions.
- Property splitting: prove positive top-level conjuncts in source order and
  share proved conjuncts at the same frame. Count a depth only after all pass.
- Scheduled exact grounding: retain as opt-in at the user's request. In its full
  suite it gains ring_leader_election 8 -> 9 checks, but loses client_server_db_ae
  12 -> 11 and flash-coherence 12 -> 10. Ordinary validated selections take precedence.
  Overall coverage is 334 versus guided 336, so this is not a default choice.

* Tomasulo progression
The CSV files retain paired runs and their individual timings. The final
pre-cleanup comparison was:

| Configuration          | Completed checks | Seconds through check 5 | Seconds through check 6 |
|------------------------+------------------+-------------------------+-------------------------|
| Proved instances       |                7 |                  69.696 |                 213.863 |
| Plus property splitting|                7 |                  53.187 |                 181.728 |
| Native Z3              |                6 |                  54.610 |                       - |

Splitting reduced time through check 6 by about 15% in that run. It did not gain
a further completed depth. The 53.2s versus 54.6s comparison is too close to
claim a robust timing win. Yardbird's extra completed check is the clearer gain.
Earlier steps moved guided search from three checks to six with read support,
then to seven with proved universal instances. The remaining check-7 stall is
in a ground solver query: the diagnostic reported about 71 million added
equalities and 30 million propagations, without native array axioms or QIs.
Diagnostic solver limits/build settings differ from confirmation timings.

* Removed experiments
Cross-rule and dependency batching did not retain compelling gains. Standalone
broad grounding was dominated by ordinary guided search. Model-indexed joins
and extraction caching preserved total depth coverage without a meaningful,
robust runtime improvement. Model replay increased ground work. Their optional
implementations and switches are removed; their evidence remains archived.
The standalone ground-binder policy is removed independently of the retained
scheduled exact-grounding option.

* Review and validation
Review covers model-local cache lifetimes, source-only index growth, literal
bindings, independent candidate validation, original-frame property reuse,
property-part activation, and timeout depth accounting. Regression tests cover
unsafe later property conjuncts, later-frame counterexamples, typed witness
substitution, read support, scheduling fallback, and benchmark progress parsing.
Review also fixed true-to-false builder toggling for property splitting and
store discovery through attributed quantified bodies. Read support is reset when
a strategy is configured for a new problem, preventing stale instances from
crossing problem boundaries at the same depth. The benchmark harness now hashes
staged edits as well as unstaged edits.

Cleanup validation completed before committing: 500 unit tests on the main-based
checkout, 15 integration tests, and 10 Python tests passed. The binary, all 288
Rust/build source files, all 30 input hashes, and baseline flags were checked.
All 30 guided cases preserved their completed-check counts; no case lost a depth.
The focused Tomasulo and exact-grounding ring-leader gains were also preserved.
The two later unsafe-property integration scenarios run with splitting both off
and on. Captured integration solver sessions contain no native arrays or QIs.
